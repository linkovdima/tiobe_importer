--- ВСТАВКА В ВВЕДЕНИЕ (после формулировки задач, перед практической значимостью) ---

Объект исследования — процессы представления, хранения и поиска структурированных
сведений о языках программирования и учебных материалах в виде семантической
модели (онтологии RDF) и веб-доступа к ним.

Предмет исследования — методы и средства построения веб-приложения семантической
электронной библиотеки: загрузка онтологии, поиск по ключевым словам, интеграция
внешних результатов поиска с записью в граф, персональный кабинет пользователя.

Методы исследования — анализ предметной области и существующих подходов к
семантическому вебу; объектно-ориентированное и модульное проектирование;
прототипирование на Python (Flask, rdflib); функциональное и нагрузочное
тестирование интерфейса API (pytest).

Структура работы: в первой главе обосновывается актуальность и формулируются цели;
во второй — предметная область и проект онтологии; в третьей — реализация
веб-приложения; в четвёртой — тестирование и оценка результатов; в заключении —
выводы и направления развития.

--- П. 2.3 (provenance для внешних источников) — заменить при необходимости ---

Для индивидов класса SourceDocument в онтологии задаются свойства, позволяющие
отследить происхождение записи: :aboutLanguage (связь с ProgrammingLanguage),
:hasSource (URI источника), :sourceName, :queryText, :retrievedAt (момент
получения результата), :confidenceScore, :title. Таким образом, фиксируются
запрос, время извлечения и ссылка на внешний ресурс.

--- ТАБЛИЦА 2.4 — привести в соответствие с programming_languages.ttl ---

Класс ProgrammingLanguage:
  • Идентификация: локальное имя именованного индивида в графе (:Python, :CSharp,
    :CPlusPlus и т.д.), отображаемое имя формируется в приложении (например,
    CPlusPlus → «C++»).
  • tiobeRank — xsd:integer (при наличии).
  • tiobeRating — xsd:string, в данных хранится как строка с символом процента
    (например, «8.03%»), не как десятичная дробь без единицы измерения.
  • yearCreated — xsd:integer (год появления языка; задаётся у индивидов языков).
Свойство yearPublished в текущей схеме для языков не используется; для публикаций
при необходимости указываются publicationDate (xsd:dateTime) и др. свойства класса
Publication.


--- П. 3.1 — заменить описание менеджера онтологии в веб-приложении ---

В серверной части веб-приложения (модуль web_dashboard.py) для чтения RDF-графа
и выдачи данных в API используется класс OntologyWebManager: загрузка файла

методы get_all_languages() и get_language_details() для маршрутов /api/languages
и /api/language/<name>. Для пакетного импорта и обновления рейтингов из скриптов
(ontology_manager.py, TIOBEImporter и др.) по-прежнему применяется класс
OntologyManager с сохранением графа на диск; в тексте ВКР целесообразно явно
разделять эти два контура, чтобы не смешивать их названиями методов.

--- П. 3.5 — ЗАМЕНИТЬ ЦЕЛИКОМ (REST API и поиск; без вымышленных маршрутов) ---

Поиск по онтологии выполняет класс OntologySearch (модуль ontology_search.py),
экземпляр которого создаётся в web_dashboard.py и используется в обработчиках
/api/search и связанных маршрутах. Единый формат JSON {success, data} для всех
эндпоинтов не используется: часть маршрутов возвращает «голый» массив или объект,
часть — объект с полем success.

Основные маршруты веб-приложения (Flask):

GET  /api/languages
  Ответ: JSON-массив объектов [{name, display_name, tiobe_rank, tiobe_rating, …}, …].

GET  /api/language/<name>
  Ответ: JSON-объект «словарь свойств» языка (ключи — локальные имена предикатов).

GET  /api/stats
  Ответ: {total_languages, languages_with_tiobe, …, last_updated}.

GET|POST /api/search
  Тело POST (JSON): обязательно keywords; опционально languages, source_type,
  source_language, difficulty, include_external_always, year, sort_by, page, per_page.
  Ответ при успехе: {success: true, keywords, total_results, page, per_page,
  total_pages, results: [...], fallback_used, avg_quality_score, …}.
  При ошибке: {success: false, error: "..."}.

GET  /api/search/language/<name>
  Ответ: {success: true, language: {...}} или {success: false, error: "..."}.

GET  /api/search/languages
  Ответ: {success: true, total, languages: [...]}.

POST /api/search/save_external
  Тело: title, url; опционально source_name, query_text, language, confidence_score.
  Ответ: {success: true, message: "..."} или {success: false, error: "..."}.

POST /api/search/save_fact
  Тело: fact_text, source_url; прочие поля по необходимости (query_text, language,
  material_type, source_name, title).
  Ответ: аналогично save_external.

GET  /api/languages/popular
  Ответ: {success: true, languages: [{name, display_name, source_count}, …]}.

Маршруты /api/publications, /api/integration/update и /api/integration/status
в текущей реализации отсутствуют; при описании перспектив их следует выносить
в подраздел «возможное развитие», а не в раздел о реализованном API.

Кабинет пользователя (SQLite, сессии): среди прочего GET/POST /api/me/folders,
GET/POST /api/me/saved, GET /api/me/export, GET /api/me/session — при отсутствии
авторизации защищённые маршруты возвращают 401 с JSON {success: false, …}.
