В эпоху цифровой трансформации электронные библиотеки становятся неотъемлемой частью информационной инфраструктуры образовательных и научных учреждений. Особую актуальность приобретают специализированные электронные библиотеки, ориентированные на конкретные предметные области, такие как программирование и информационные технологии. Такие библиотеки должны обеспечивать эффективный доступ к библиографическим ресурсам, структурированную организацию знаний и интеллектуальный поиск информации.

Традиционные библиотечные системы, основанные на реляционных базах данных и простом текстовом поиске, имеют существенные ограничения: они не учитывают семантические связи между ресурсами, не поддерживают интеллектуальный поиск по смыслу и затрудняют интеграцию данных из различных источников. Решение этих проблем требует применения современных семантических технологий, в частности, онтологий и связанных данных (Linked Data).

Семантические технологии позволяют не только хранить библиографические данные, но и описывать их смысл, связи между публикациями, авторами, темами и языками программирования. Это открывает возможности для семантического поиска, автоматического вывода новых знаний, рекомендательных систем и интеграции с другими библиотечными каталогами.

1. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ РАЗРАБОТКИ СЕМАНТИЧЕСКОЙ ЭЛЕКТРОННОЙ БИБЛИОТЕКИ

1.1. Электронные библиотеки: понятие, классификация, особенности

Электронная библиотека представляет собой информационную систему, предназначенную для хранения, организации, поиска и предоставления доступа к электронным документам и библиографическим ресурсам. В отличие от традиционных библиотек, электронные библиотеки обеспечивают удаленный доступ к ресурсам через веб-интерфейс, что делает информацию доступной в любое время и из любого места.

Основные характеристики электронных библиотек:

1. Цифровое хранение ресурсов – все документы хранятся в электронном виде, что обеспечивает их сохранность и возможность быстрого доступа.

2. Метаданные и каталогизация – каждый ресурс описывается метаданными (название, автор, тематика, ключевые слова и т.д.), что позволяет эффективно организовывать и искать информацию.

3. Поисковые возможности – электронные библиотеки предоставляют различные механизмы поиска: по названию, автору, ключевым словам, тематике.

4. Многоуровневая организация – ресурсы могут быть организованы по различным критериям: по темам, типам публикаций, языкам программирования и т.д.

5. Интеграция с внешними источниками – возможность подключения к другим библиотечным системам и базам данных.

Классификация электронных библиотек:

По типу контента:
- Универсальные библиотеки (содержат ресурсы по различным темам);
- Специализированные библиотеки (ориентированы на конкретную предметную область, например, программирование).

По способу организации:
- Централизованные (единое хранилище данных);
- Распределенные (данные хранятся в различных местах, но доступны через единый интерфейс).

По технологии поиска:
- Традиционные (текстовый поиск по метаданным);
- Семантические (поиск с учетом смысла и связей между ресурсами).

Особенности специализированных электронных библиотек по программированию:

1. Структурированная организация по языкам программирования – ресурсы связаны с конкретными языками (Python, Java, JavaScript и т.д.).

2. Разнообразие типов публикаций – книги, статьи, документация, туториалы, видеокурсы.

3. Актуальность информации – необходимость регулярного обновления данных о новых версиях языков, фреймворков, библиотек.

4. Связи между ресурсами – публикации могут быть связаны с языками, фреймворками, темами, авторами.

5. Рекомендательные системы – возможность предлагать пользователям релевантные ресурсы на основе их интересов.

Преимущества электронных библиотек перед традиционными:

- Доступность 24/7 из любой точки мира;
- Одновременный доступ множества пользователей к одному ресурсу;
- Быстрый поиск и навигация;
- Возможность интеграции с другими системами;
- Автоматизация процессов каталогизации и индексации;
- Мультимедийный контент (видео, интерактивные материалы).

1.2. Семантические технологии и онтологии в библиотечных системах

Семантические технологии представляют собой набор методов и инструментов, предназначенных для работы со структурированными данными, которые несут в себе не только информацию, но и смысл (семантику). Основой семантических технологий является концепция семантической паутины (Semantic Web), предложенная Тимом Бернерсом-Ли в начале 2000-х годов.

Семантическая паутина расширяет возможности традиционного веба, добавляя к данным метаданные, которые описывают их смысл и связи. Это позволяет машинам не только обрабатывать данные, но и понимать их контекст и семантику.

Ключевыми стандартами семантической паутины являются:

1. RDF (Resource Description Framework) – модель данных для представления информации о ресурсах в виде триплетов (субъект, предикат, объект). RDF позволяет описывать ресурсы и их свойства в формате, понятном машинам.

2. RDFS (RDF Schema) – язык для описания словарей RDF. RDFS позволяет определять классы, свойства и иерархии, что делает возможным создание простых онтологий.

3. OWL (Web Ontology Language) – более мощный язык для создания онтологий, поддерживающий логический вывод, ограничения и сложные отношения между сущностями. OWL имеет три профиля:
   - OWL Lite – упрощенная версия для базовых онтологий;
   - OWL DL – полная версия с поддержкой дескриптивной логики;
   - OWL Full – максимально выразительная версия без ограничений.

4. SPARQL (SPARQL Protocol and RDF Query Language) – язык запросов для RDF данных, аналогичный SQL для реляционных баз данных.

Онтология в контексте информатики представляет собой формализованное описание предметной области, включающее:
- Классы (Concepts) – основные понятия предметной области;
- Свойства (Properties) – атрибуты и отношения между классами;
- Индивиды (Individuals) – конкретные экземпляры классов;
- Аксиомы – правила и ограничения, описывающие логику предметной области.

Онтологии позволяют:
- Структурировать знания о предметной области;
- Обеспечивать единообразие терминологии;
- Поддерживать логический вывод новых знаний;
- Обеспечивать семантический поиск;
- Интегрировать данные из различных источников.

Применение семантических технологий в библиотечных системах открывает новые возможности:

1. Семантический поиск – поиск не только по точным совпадениям, но и по смыслу, связям и контексту. Например, поиск "объектно-ориентированное программирование" может находить ресурсы о Java, C++, Python, даже если эти термины не упоминаются напрямую.

2. Интеграция данных – возможность объединения каталогов из различных библиотек в единую семантическую сеть связанных данных (Linked Data).

3. Автоматический вывод знаний – система может автоматически выводить новые связи. Например, если книга связана с языком Python, а Python связан с парадигмой ООП, то система может автоматически связать книгу с парадигмой ООП.

4. Рекомендательные системы – на основе семантических связей система может рекомендовать пользователям релевантные ресурсы.

5. Многоязычность – семантические технологии позволяют описывать ресурсы на разных языках, сохраняя при этом семантические связи.

Преимущества использования онтологий в электронных библиотеках:

1. Гибкость структуры данных – легко добавлять новые типы публикаций, свойства и связи без изменения существующих данных.

2. Единообразие терминологии – онтология обеспечивает единый словарь терминов для всей библиотеки.

3. Расширяемость – возможность добавления новых классов и свойств по мере развития библиотеки.

4. Стандартизация – использование открытых стандартов (OWL, RDF) обеспечивает совместимость с другими библиотечными системами.

5. Интеграция с внешними источниками – возможность подключения к другим семантическим библиотекам и базам данных.

1.3. Онтологии для описания библиографических ресурсов

TIOBE Index (TIOBE Programming Community Index) является одним из наиболее авторитетных рейтингов популярности языков программирования. Индекс публикуется ежемесячно компанией TIOBE Software и отражает популярность языков программирования на основе анализа поисковых запросов в популярных поисковых системах (Google, Bing, Yahoo!, Wikipedia, Amazon, YouTube и Baidu).

Методология расчета TIOBE Index:

1. Сбор данных – система анализирует количество поисковых запросов вида "+<language> programming" в указанных поисковых системах.

2. Нормализация – результаты нормализуются относительно общего числа запросов, связанных с программированием.

3. Расчет рейтинга – для каждого языка вычисляется процент от общего числа запросов, что и составляет его рейтинг.

4. Ранжирование – языки сортируются по убыванию рейтинга, что определяет их позицию в индексе.

TIOBE Index предоставляет следующие данные для каждого языка:
- Ранг (позиция в рейтинге);
- Рейтинг (процент популярности);
- Изменение рейтинга по сравнению с предыдущим месяцем;
- Тренд (растущий, падающий, стабильный).

Структура данных TIOBE Index представлена в виде таблицы на веб-сайте tiobe.com, где каждый язык программирования имеет свою строку с соответствующими метриками.

Для автоматического получения данных из TIOBE Index необходимо решить следующие задачи:

1. Веб-скрапинг – извлечение данных из HTML-страницы сайта TIOBE. Это требует анализа структуры HTML, поиска нужных элементов и парсинга текстовых данных.

2. Обработка данных – преобразование извлеченных данных в структурированный формат (JSON, XML или RDF).

3. Нормализация названий языков – приведение названий языков к единому формату (например, "C++" → "CPlusPlus" для использования в URI).

4. Обработка ошибок – учет возможных изменений в структуре сайта, сетевых ошибок и других проблем.

В разработанной системе для получения данных из TIOBE Index используется библиотека BeautifulSoup для парсинга HTML и библиотека requests для выполнения HTTP-запросов. Реализованы несколько стратегий получения данных:
- Прямой парсинг HTML-страницы TIOBE;
- Использование улучшенного парсера с обработкой различных форматов данных;
- Резервный режим с демо-данными для тестирования.

Существует несколько стандартных онтологий для описания библиографических ресурсов, которые могут быть использованы в электронных библиотеках:

1. Dublin Core – простой набор из 15 основных элементов метаданных (название, автор, тема, дата и т.д.). Dublin Core широко используется для базового описания ресурсов.

2. BIBO (Bibliographic Ontology) – онтология для описания библиографических цитат и ссылок. BIBO расширяет Dublin Core и FOAF, добавляя специфичные для библиографии классы и свойства.

3. FRBR (Functional Requirements for Bibliographic Records) – концептуальная модель для описания библиографических записей. FRBR описывает иерархию: Work → Expression → Manifestation → Item.

4. MARC (Machine-Readable Cataloging) – стандарт для представления библиографических данных в машиночитаемом формате. MARC широко используется в традиционных библиотечных системах.

5. Schema.org – коллекция схем для структурированных данных в вебе. Включает классы Book, Article, CreativeWork и другие, полезные для описания библиотечных ресурсов.

В контексте специализированной библиотеки по программированию необходимо расширить стандартные онтологии, добавив:

- Классы для языков программирования (ProgrammingLanguage);
- Классы для фреймворков и библиотек (Framework, Library);
- Связи между публикациями и языками программирования;

1.5. Методы семантического поиска в библиотечных каталогах

Семантический поиск в библиотечных каталогах принципиально отличается от традиционного текстового поиска. Вместо простого сопоставления ключевых слов, семантический поиск учитывает смысл запроса и связи между ресурсами.

Основные методы семантического поиска:

1. Поиск по ключевым словам с учетом синонимов:
   - Использование тезаурусов и словарей синонимов;
   - Расширение запроса синонимами и связанными терминами;
   - Пример: запрос "ООП" может находить ресурсы о "объектно-ориентированном программировании".

2. Поиск по связям (Relationship-based search):
   - Поиск ресурсов, связанных с указанными сущностями;
   - Пример: поиск "книги о Python" найдет все книги, связанные с языком Python через свойство aboutLanguage.

3. Контекстный поиск:
   - Учет контекста запроса;
   - Понимание намерений пользователя;
   - Пример: запрос "изучение веб-разработки" может находить ресурсы о JavaScript, HTML, CSS, фреймворках.

4. Фасетный поиск (Faceted search):
   - Поиск с фильтрацией по различным аспектам (язык, тип публикации, автор, год);
   - Позволяет пользователю постепенно уточнять результаты поиска.

5. Ранжирование по релевантности:
   - Вычисление релевантности результатов на основе:
     * Количества совпадений ключевых слов;
     * Близости связей в онтологии;
     * Популярности ресурса;
     * Времени публикации.

Реализация семантического поиска с использованием SPARQL:

SPARQL позволяет формулировать сложные запросы, учитывающие семантические связи. Например, запрос "найти книги о языках программирования с объектно-ориентированной парадигмой" может быть выражен следующим образом:

```sparql
SELECT ?book ?title ?language WHERE {
  ?book a onto:Book .
  ?book onto:title ?title .
  ?book onto:aboutLanguage ?language .
  ?language onto:hasParadigm onto:OOP .
}
```

Преимущества семантического поиска:

- Более точные результаты – поиск по смыслу, а не только по словам;
- Обнаружение скрытых связей – нахождение ресурсов, связанных косвенно;
- Персонализация – учет контекста и предпочтений пользователя;
- Многоязычность – поиск работает независимо от языка описания ресурсов.

Ограничения и вызовы:

- Сложность реализации – требует тщательной разработки онтологии;
- Производительность – семантические запросы могут быть медленнее простых текстовых;
- Качество онтологии – результаты поиска зависят от качества и полноты онтологии.

3. РЕАЛИЗАЦИЯ ПРОТОТИПА ВЕБ-ПРИЛОЖЕНИЯ

3.1. Модуль управления онтологией и каталогом

Модуль TIOBEImporter отвечает за получение данных о рейтингах языков программирования с сайта TIOBE. Основные функции модуля:

1. scrape_tiobe_ranking() – основная функция для получения рейтингов. Использует несколько стратегий:
   - Сначала пытается использовать ImprovedDataFetcher для получения реальных данных;
   - Если не удалось, использует AdvancedTIOBEParser;
   - В случае ошибок использует демо-данные для тестирования.

2. _parse_tiobe_page() – парсинг HTML-страницы TIOBE. Функция:
   - Ищет таблицу с рейтингами используя различные селекторы;
   - Извлекает ранг, название языка и рейтинг;
   - Нормализует названия языков.

3. _normalize_language_name() – нормализация названий языков для использования в URI. Преобразует:
   - "C++" → "CPlusPlus"
   - "C#" → "CSharp"
   - Удаляет специальные символы.

4. _fix_ranking_issues() – исправление проблем с распознаванием данных. Обрабатывает:
   - Проблемы с языком "C" (может парситься как "+0.91%");
   - Различные варианты написания названий;
   - Фильтрацию только целевых языков (6 языков: Python, Java, JavaScript, C, C++, C#).

5. update_ontology_with_rankings() – обновление онтологии новыми рейтингами. Для каждого языка:
   - Удаляет старые значения tiobeRank и tiobeRating;
   - Добавляет новые значения;
   - Логирует результаты.

3.2. Модуль каталогизации публикаций

Модуль OntologyManager обеспечивает работу с онтологией на уровне RDF-графа. Основные функции:

1. load_ontology() – загрузка онтологии из файла. Функция:
   - Проверяет существование файла;
   - Парсит файл в формате Turtle;
   - Выводит статистику о загруженных данных.

2. save_ontology() – сохранение онтологии в файл. Сохраняет в формате Turtle с сохранением структуры.

3. language_exists() – проверка существования языка в онтологии. Используется перед обновлением данных.

4. update_language_ranking() – обновление рейтинга языка. Функция:
   - Проверяет существование языка;
   - Удаляет старые значения свойств;
   - Добавляет новые значения;
   - Обрабатывает ошибки.

5. get_language_info() – получение информации о языке. Возвращает словарь с данными о языке.

```python
class OntologyManager:

        self.g = Graph()  # RDF-граф

        self.NS = Namespace("...")  # Пространство имен
```

3.3. Модуль семантического поиска

Модуль OntologySearch реализует семантический поиск по онтологии с использованием SPARQL-запросов. Основные функции:

1. search_by_keywords() – поиск по ключевым словам. Функция:
   - Разбивает запрос на ключевые слова;
   - Ищет в публикациях, языках и фреймворках;
   - Ранжирует результаты по релевантности;
   - Удаляет дубликаты.

2. _search_in_publications() – поиск в публикациях. Использует SPARQL-запрос для поиска по:
   - Названию публикации;
   - Ключевым словам;

А.2. Модуль управления онтологией (ontology_manager.py)

Основные функции модуля:

```python
class OntologyManager:
    def __init__(self, ontology_path=None):
        self.g = Graph()
        self.ontology_path = ontology_path or ONTOLOGY_PATH
        self.NS = Namespace("http://www.semanticweb.org/...")
        self.load_ontology()
    
    def load_ontology(self):
        """Загрузка онтологии из файла"""
        try:
            if os.path.exists(str(self.ontology_path)):
                self.g.parse(str(self.ontology_path), format="turtle")
                return True
        except Exception as e:
            print(f"Ошибка загрузки: {e}")
            return False
    
    def update_language_ranking(self, language_name, rank, rating):
        """Обновление рейтинга языка"""
        if not self.language_exists(language_name):
            return False
        
        lang_uri = self.NS[language_name]
        
        # Удаляем старые значения
        self.g.remove((lang_uri, self.NS.tiobeRank, None))
        self.g.remove((lang_uri, self.NS.tiobeRating, None))
        
        # Добавляем новые
        self.g.add((lang_uri, self.NS.tiobeRank, Literal(int(rank))))
        self.g.add((lang_uri, self.NS.tiobeRating, Literal(rating)))
        
        return True
```

```sparql
}
```

Б.4. Запрос для получения публикаций конкретного языка

```sparql
SELECT ?pub ?title ?type WHERE {
  ?pub onto:aboutLanguage onto:Python .
  ?pub onto:title ?title .
  ?pub a ?type .
  FILTER(?type IN (onto:Book, onto:Article, onto:Documentation))
}
```

Б.5. Запрос для получения статистики

```sparql
SELECT 
  (COUNT(DISTINCT ?lang) AS ?total_languages)
  (COUNT(DISTINCT ?pub) AS ?total_publications)
WHERE {
  { ?lang a onto:ProgrammingLanguage . }
  UNION
  { ?pub a ?pubType .
    FILTER(?pubType IN (onto:Book, onto:Article)) }
}
```
